# DOCX 编辑保存诊断与短期增强方案

功能：记录保存失真证据、当前能力及 GenOffice 复用边界；时间：2026-11-07；作者：lq。

## 结论

当前首先需要解决编辑保存的信息损失。Mini Office 显示正常，只说明浏览器能渲染已经解析的模型；Word 再打开时读取的是重新写出的 OOXML，两条链路并不等价。已复现「表格改一个字，未编辑的合并续行边框丢失」。现有能力适合基础文档编辑，尚不能作为复杂 Word 文档可靠往返的通用内核。

建议先建立原始 OOXML 的细粒度保存，再用真实样本对完整 GenOffice Docs 内核做隔离接入实验。完整内核通过验收后替换 Word 文档区域；如果继续零散移植解析与显示规则，需要持续承担两套模型、编辑行为和分页规则的一致性成本。

## 已定位的保存机制问题

1. `source-preservation.ts` 的来源分组以顶层正文元素为单位。`patchText()` 只接收单一顶层段落；顶层表格内任何文字变化都会令整张表进入 `serialize.ts/tableXml()` 重建。
2. `parse.ts/parseTable()` 将纵向合并续格折叠为首格的 `rowSpan`，没有保留续格独立的边框、底纹等源属性。显示层可以使用合并后的大格渲染，因此不暴露全部保存信息缺口。
3. `tableXml()` 重建合并续格时仅提供空内容、合并跨度及列宽，没有原续格 `tcPr`；源文件未设置表格级通用边框时，续格边框丢失。重建还可能把有效继承格式展开成直接格式。
4. 普通文字补丁要求 run 数量和样式完全吻合。编辑区通过 contenteditable DOM 回读，浏览器合并 run、输入法或样式规范化可能导致纯输入也无法命中补丁，需要真实交互覆盖。
5. 顶层 TOC 会禁用来源快照；修改页面、节或页眉页脚会退出当前来源补丁模式。这些路径仍可能使未编辑正文重建，细粒度保护尚不完整。

## 当前 Word 能力

| 方面 | 当前事实 | 适用边界 |
| --- | --- | --- |
| DOCX 导入 | 有样式、段落、表格、节、页眉页脚等模型 | 模型并非完整 OOXML，未建模信息依赖源 XML 留存 |
| 无操作保存 | 有条件原始字节透传，本次两份文件通过 | 不代表编辑保存可靠；无来源快照等路径另行处理 |
| 普通段落编辑 | 有局部文本补丁、内容和格式编辑 | run 结构变化及复杂段落可能重建 |
| 表格编辑保存 | 有行列、合并和表格生成器 | 合并续格属性已实证丢失，属于优先修复项 |
| 排版分页 | 自研 HTML/CSS、字体度量、DOM 测量及分页 | 浏览器与桌面 WebView、Microsoft Word 之间尚无通用一致保证 |
| 复杂内容 | 部分内容解析或源片段保留 | 源片段能够保留，不等于能准确显示并编辑 |

## GenOffice 能否直接复用

可以复用，但解析、编辑、保存和排版属于相互关联的模块。

本地固定上游 `e1f50e90d246f3ecc6427d2a0af90f04f37810ec` 的 `packages/docx-engine/src/generate.ts` 已包含 `patchTableCellTexts()`，按物理行与物理单元格定位，保留表格结构，只修改目标格内容；支持部分嵌套表格场景。其行模型包含纵向合并续格，与 Mini Office 折叠后的模型不同，不能直接用当前 cell 下标调用。需要稳定的源行、源格、源段落锚点与补丁成功检查。

目前引入的是 DOC 转换、生成依赖、XML 扫描/文本补丁及少量字体度量。`third_party/genoffice/engine-entry.ts` 没有导出其 DOCX 解析和保存入口；产品 Word 区域依然是 Mini Office 自己的 `WordEditor.tsx`、`parse.ts`、`serialize.ts`、`pagination.ts`。

上游排版分布于 Docs renderer 的编辑 schema、字体行盒、表格显示、分页测量/切片与页眉页脚。其编辑部分使用 Tiptap/ProseMirror；当前本地使用自定义 contenteditable，React 主版本和桌面宿主也不同。单独替换 docx-engine 会改善导入保存基础，但不会自动替换屏幕分页。

建议以固定版本的 `docx-engine + Docs 编辑与排版核心 + font-metrics` 为迁移单元，保留本项目工作区、文件标签、平台适配和其他文档类型。由明确的适配层提供打开、编辑状态、保存、选区命令、只读和资源释放；避免每次编辑把完整上游模型转成现有简化模型再转回。Electron 文件/字体/打印接口需要接入本项目 Tauri 平台层。

参考：[当前引擎入口](https://github.com/genspark-ai/genoffice/blob/main/packages/docx-engine/src/index.ts)、[当前 Docs 依赖](https://github.com/genspark-ai/genoffice/blob/main/apps/docs/package.json)、[固定版本单元格补丁](https://github.com/genspark-ai/genoffice/blob/e1f50e90d246f3ecc6427d2a0af90f04f37810ec/packages/docx-engine/src/generate.ts)。上游声明的保真能力必须以本项目样本实测，不能作为验收结果。

## 短期执行方案与通过门槛

以下是排期建议，依赖实际开发投入与适配结果，不是交付保证。

### 第一阶段：先使常见小改动可靠保存，约 2–4 个工作日

- 为表格、物理行、物理格和段落建立源锚点；纯文本编辑只改目标文字。使用或移植经过验证的单元格补丁，不让单字编辑进入整表生成。
- 格式编辑按属性组替换，保留未知属性；结构编辑单独处理物理续格、边框、列宽、合并关系、行高和内边距。无法确认补丁安全的操作必须返回明确失败，不静默回退为有损重建。
- 无法支持的复杂对象先保持原始内容并限制对应编辑；不将“能识别表格”统一当作安全编辑资格。默认保护原件，提供可恢复的保存副本。
- 覆盖中文输入法、粘贴、空段、回车、字体与字号修改、表格文字修改及连续保存/撤销。测试必须走真实编辑输入，再保存检查 XML。
- 验收：不改动时字节一致；单字修改只改变对应文字和必要属性，所有非目标表格属性保持；连续重开保存不漂移；在实际 Word 打开后检查表格及分页。文字变长引起正常重排属于预期，未编辑结构丢失属于失败。

### 第二阶段：完整 GenOffice 内核验证，约 3–5 个工作日

- 建立隔离实验入口，固定版本，先接入完整引擎和编辑区，适配本地文件、字体与图片；不在此阶段重做工具栏外观。
- 选 10–20 份代表性文件：本次原件/保存件、合并表格、合同、目录、分节页眉页脚、浮动图片、跨页长表。相同文件分别通过当前实现和候选实现打开、真实编辑保存、由 Word 重开。
- 三组独立指标：源 XML 与非目标部件保持、Word 重开版式、桌面 WebView 显示/交互；同时记录启动性能、内存和实际安装包增量。
- 候选内核必须先证明本例和代表集优于现有实现。若上游自身仍损坏目标文档，记录失败并修复或重新选型，不直接全量迁移。

### 第三阶段：通过后替换产品 Word 区域，预估再需 1–3 周

- 完成工具栏命令、撤销重做、输入法、文件会话、打印与平台资源管理适配，逐步切换现有功能。
- 保留固定版本和补丁清单，减少修改上游核心，便于后续更新。
- 正式发布门槛是代表集实际 Word 往返验收与桌面实测，不能只要求编译和单元测试通过。

如果需求是短期覆盖任意复杂 Word 文件，单靠一两周的自研修补或 GenOffice 移植无法作出可靠保证。可另行评估成熟完整文档引擎，但离线体积、跨平台、许可和真实样本保真都需验证。本项目当前最可控的近期目标是明确支持范围内的文本/格式修改可靠往返，并让复杂内容得到保护。

## 第一阶段保存修复实施结果

功能：修复常见正文及表格编辑保存损失，并为未经验证的回写提供失败保护；时间：2026-11-07；作者：lq。

### 已实现

- 新增 `packages/editor-word/src/source-block-patch.ts`，以导入快照中的稳定块 ID、直接子节点区间及原始物理行格顺序定位。纵向合并续格直接保留原 XML，嵌套表格递归处理。
- 普通文字修改仅补目标文字；同格式 run 合并可识别。单一源 run 的多行输入、Tab 及格式分片可沿用源字符属性；复杂情形须通过对应检查。
- 字体、字号、加粗、段落对齐、部分行格属性按属性组更新，保留原书签、语言、行格属性及未知兄弟节点。行距和缩进进一步按属性更新，避免覆盖同组自动段距和字符缩进。
- 支持格内新增、删除段落的稳定锚点保存，保持 tcPr 在内容之前。空段落的结束标记字体单独更新。
- 页面变化需要重建文档外壳时，仍保留已定位的源段落与表格。修复带 rsid 属性的分节段落定位，并避免重复追加 sectPr。
- 无法安全处理的导入表格结构编辑、复杂域变化、复合来源段落重建或导入定位失败，返回 `SAVE_FAILED`。保存生命周期测试确认不会调用磁盘写入，并保留 dirty 状态与源缓冲。
- 邮件合并控制器挂载不再把默认面板状态写入普通文档；保留已有模板关系及空值策略。已有合并配置相同的保存也可返回原字节。
