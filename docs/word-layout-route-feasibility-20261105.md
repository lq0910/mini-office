# 自研 Word 排版内核的模块复用路线验证

功能：记录模块复用路线的实测证据、限制与推进门槛；时间：2026-11-05；作者：lq。

## 结论与范围

路线有条件可行：保留自研文档模型和排版内核，选择性复用经逐文件核对许可的 GenOffice 模块；结合格式规范、行为实验和 LibreOffice 输出分析规则后自主实现。此结论不等于通用 Word 高保真已完成，也不证明完整 GenOffice 内核容易拆分。

## 已取得的证据

- `third_party/genoffice/engine-entry.ts` 仅暴露 DOC 转换需要的生成接口，构建脚本把转换、XML 扫描和 XML 文本补丁拆为独立模块。JSZip、CFB、fflate 和 XML 解析器仍是外部依赖；转换器自身大小不能当作总安装包增量。
- `packages/editor-word/src/word-font-metrics.ts` 是已有的小规模样板：取固定上游提交的五个常用中文字体族度量，自研测量层调用，不带字体文件。其模块体积证明这种粒度可以轻量引入，不能代替所有字体和完整排版的验证。
- 本轮实际执行了现有前端测试：608 项通过，3 项私有样本因未提供样本环境变量跳过；不是新增 608 项，也不是本轮重新完成私有样本视觉验收。排版度量测试 19 项、GenOffice 公开语料测试 24 项通过。`pnpm build` 通过。
- 本机 `soffice --version` 可运行，为 LibreOfficeDev 26.8.0.0.alpha0，提交 2c87e51eeaa2b413ff4ae097b2705eea1995d8e5。此开发版只适合作为额外实验参照；不能将其排版结果直接当作 Microsoft Word 真值。
- LibreOfficeDev 成功把 `tests/fixtures/docx/contract.docx` 导出到独立临时目录 PDF；PDF 信息为 2 页、A4。Fontconfig 报告缓存目录不可写，因此字体条件尚未统一；此烟测只证明参照引擎可运行，不据此判断视觉一致性。
- 当前生产构建把 GenOffice DOC 转换器输出为独立惰性 chunk，185.21 KB（gzip 65.60 KB）；它依赖的库打入该 chunk。字体度量模块单独压缩构建为 386 bytes（gzip 261 bytes），但这是隔离模块测量值，不是整包净增量。`soffice` 未集成进产品，因此安装包增量为 0。

## 许可边界

- 固定 GenOffice 源码版本 e1f50e90d246f3ecc6427d2a0af90f04f37810ec；现有 LICENSE 为 Apache-2.0，保留 LICENSE、NOTICE、原作者归属与修改记录。新增模块及其传递依赖必须重新核对，不能将仓库根许可无条件套到每个文件。
- LibreOffice 仅作为开发时参照时，无需随产品打包。复制或逐句翻译源码与独立实现规则是不同路径；语言转换不能自动消除派生代码义务。若确需复用源码，应独立存放并核对文件级及依赖许可，不承诺仅凭进程边界或目录隔离即可消除义务。
- 本轮没有引入 LibreOffice 源码、运行库、新依赖或字体文件，没有完成商业分发法律审查。

## 下一步实施门槛

1. 先固定字体、兼容设置和单位换算，以公开、最小化 DOCX 对照 Word 导出 PDF；LibreOffice 输出用于解释差异。
2. 优先处理已定位的字体行高、段落盒模型和表格边界；每项记录格式依据、上游版本、代码来源和独立行为断言，不对具体文件名添加坐标补丁。
3. 每次模块引入分别测量编译模块、gzip、完整 Web 构建及原生安装包；未生成原生包时不汇报安装包增量。
4. 以文本结构、保存回读、行盒坐标、分页点及表格边界分别验收；单元测试通过不替代 Word 视觉一致。
5. 分栏、复杂环绕、字体替代和编辑时增量重排仍需独立验证。缺页问题继续按用户要求暂缓，不借本次路线验证宣称解决。
