## 结果与当前产品状态

**M1 核心提取已完成。** `packages/word-core` 已成为独立 workspace 包，具备解析、编辑 schema、模型转换、排版算法、序列化、会话和解析 Worker。来源固定为 `e1f50e90d246f3ecc6427d2a0af90f04f37810ec`，不依赖临时源码目录构建。

现有 Word 页面、工具栏、产品 UI 和保存入口均未切换，默认仍使用原有实现。没有升级 React；新核心不引入上游 App、Ribbon、AI 服务或 Electron。接到产品页面属于 M2，现有工具栏逐项融合属于 M3，工作区和原生服务接线属于 M4。

## 关键定制

### 保留我们的命令与 UI 方向

`WordCoreSession.editor` 暴露同源编辑实例，后续由现有 Word 事件处理函数直接调用，不新建通用命令中转系统。会话订阅只报告修订版本、dirty、可撤销/重做等摘要，正文仍然只存在于新核心中。

本轮没有改 `WordToolbar.tsx`、`WordEditor.tsx`、原格式处理器或工作区 store，也没有让原工具栏读取假的新模型状态。新核心的能力与产品切换进度分开记录。

### 事务和保存生命周期

- `prepareSave()` 捕获当前事务 JSON、非正文保存选项和修订号，只生成字节；不写盘，不清 dirty，也不提前替换来源。
- `acknowledgeSave()` 只能确认此会话发出的快照，拒绝跨会话、重复及过期确认。生成后继续输入时，确认旧版本仍保持 dirty。
- 会话继续以导入来源及稳定锚点生成后续保存计划，不因一次快照提前重置编辑历史或来源。正式产品中写盘确认、重解析重定位及并发保存收敛仍在 M2/M4 接线和扩展，不能把当前基础会话视为工作区迁移已完成。
- 只读在事务过滤和保存入口同时约束，不能通过代码调用命令绕过 UI 禁用状态。
- 输入法组合输入由 ProseMirror 处理；组合期间拒绝生成保存快照，防止把候选拼音作为最终正文写盘。组合状态中的临时事务不等于已经确认的正文。

### 原 XML 的本地增强

融合测试发现：上游的 rich-cell 段落重建分支保留了格属性和合并续格，但会丢掉被编辑段落的外壳属性及书签。没有放宽断言绕过问题，而是在 `generate.ts` 增加保守的纯文字快路径：

1. 段落对应关系未变；
2. 段落格式未变，run 结构和非文字字节匹配；
3. 不含需要重建的换行/Tab 等控制语义；
4. 满足条件时使用原始 `patchParagraphTexts`，保留段落属性、书签及未编辑节点。

不符合条件的复杂改动仍进入原有的结构生成逻辑。本轮没有宣称所有结构编辑都已达到逐字节保留；M2/M3 继续针对实际动作处理。该定制由提取脚本自动应用并记录，不能通过重新复制上游文件悄悄覆盖。

修改时间和修订号是保存时允许变化的元数据。定向测试只对 `docProps/core.xml` 的这两个字段作明确例外，其余非目标部件仍逐字比较；不把元数据正常更新当作兼容损坏，也不放行整个元数据部件的任意变化。

### 平台边界与 React

`WordPlatform` 仅描述真实使用的原生字体度量、图片剪贴板和解析 Worker 创建能力；没有全量 `window.desktop` 替身。未提供原生能力时，能力摘要明确为 false，不能返回伪成功。

- 字体：保留内嵌字体、静态度量、浏览器实际 Canvas 和字体表规则；系统字体度量通过现成 provider 入口注入。Tauri 原生读取与宿主接线在 M4 完成，字体名称列表不被当成度量结果。
- 剪贴板：宿主可提供实际图片写入；未接通时保留上游 HTML-only 的回退及“写入确认后才剪切”逻辑，不提前删除图片。
- Worker：宿主注入真正的 module Worker。未提供时有明确 inline 计数；构建提供实际 Worker 入口，浏览器检查确认走了 Worker 而非回退。
- 未暴露 Node 的 ZIP 原始拼接入口；正常 DOCX 解析/保存继续走浏览器可用链路。必要 ZIP 限制和原部件保留并未删除。
- 原生打印、文件对话框、备份和产品关闭行为继续由 Mini Office 的 M4 工作区/平台融合承接。

独立构建图确认没有 React、React DOM 或 Electron 输入。因此此次接入没有升级 React 19 的前置需要，现有 React 18 工具栏继续保留。此结论针对本次架构，不是对未来所有依赖升级的永久限制。

## 构建与资源边界

`pnpm word-core:build` 同时生成浏览器 ESM、独立解析 Worker、文档 CSS、字体 CSS/资源与许可，随后核验来源和真实依赖版本。构建遇到 `node:`、Electron 或未处理的 `@genoffice/*` 导入时直接失败，不生成空模块掩盖错误。

本次构建有 394 个输入、61 个 JS/CSS/资源输出；总输出为 19,859,514 字节，其中 JS 4,942,923 字节、CSS 240,691 字节，字体 14,675,900 字节。这是独立核心包的未压缩构建输出，**不是当前 Mini Office 安装包的净增量**；核心尚未加入产品路由，尚未进行原生打包。后续根据真实格式覆盖收敛资源，不能直接删掉 Word 所需的替代字体和度量规则。

上游字体仍保留原有声明名称，产品 UI 不因此改变字体或品牌。新增解析依赖 `@nodable/entities@3.1.0` 的 npm 包遗漏完整许可，已按其 npm `gitHead` 从官方固定提交取得原文，来源和 SHA-256 记录在 `licenses/SOURCES.json`，构建可离线使用。
