## 文件格式和保存规则

| 格式或情形 | 当前源码的实际规则 | 迁移要求 |
| --- | --- | --- |
| `.docx` | 解析后按能力级别进入可编辑/只读或副本保存；满足条件可原位保存 | 新核心承接同一平台保存机制及备份，未确认写盘成功前不清 dirty |
| `.doc` | 本地兼容转换成 OOXML；保留原名展示，解除原路径绑定，另存 `.docx` | 不把 OOXML 字节写回 `.doc`，不把转换称为原格式无损保存 |
| `.docm` | 扩展名映射 Word；检测到 VBA 部件会触发 blocking、只读 | 不执行宏；若以后改变编辑资格，必须先实现完整部件和扩展名保留，不能自动解除保护 |
| `.dotx` | 当前按 Word 打开，保存名由 `saveNameFor` 规范为 `.docx`；尚无独立模板写回策略 | 显式承接模板转文档语义，不把“能打开”当作模板原位保真回写已经实现 |
| 数字签名 | 检测到签名部件时只读 | 不声称编辑后签名仍有效 |
| 修订、批注、内容控件、嵌入对象等 | 现有兼容报告按不同场景提示，部分只保留不可编辑 | 新核心接通后逐项更新能力；不能沿用旧警告把新能力错误降级 |
| 恢复的 dirty 快照 | 打开为待保存副本，重新选择目标 | 不静默覆盖旧业务文件 |
| 另存为取消、序列化失败、写盘失败 | 返回失败并保留未保存状态 | 新核心生成字节与保存确认分开，原始包/锚点不提前替换 |

表中的当前行为来自 `packages/document-model/src/store.ts`、`packages/editor-word/src/handler.ts`、`packages/ooxml/src/capabilities.ts` 和平台实现。M0 不修改这些规则；本表明确记录现状中的限制，后续变更需要对应实现和行为依据。

功能：M3 已于 2026-11-11 完成现有 W01–W35 工具栏、区域、邮件及输出接入；逐项实现、756 项测试、M3 131 项浏览器检查及结构支持边界见 [M3 验收记录](../word-core-m3/README.md)。W36–W38 的完整桌面平台/生命周期与默认交付继续按 M4/M5；时间：2026-11-11；作者：lq。
