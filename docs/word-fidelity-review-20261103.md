# 三份真实 Word 样本的保真评审与根治路线

- 功能：评审当前未提交优化，记录实际证据、提交阻断项和架构建议。
- 时间：2026-11-03；作者：lq。
- 基线：`main`，HEAD `21904ce`；评审对象为当前工作区改动，Git 暂存区为空。
- 本次只新增本评审文档，不修改现有业务代码，也不提交或推送。

## 结论

现有优化中，临时转换隔离、显式编辑标记、补齐 OOXML 属性、统一度量入口的方向值得保留。
但当前实现存在会改变原文、清除未保存标记、破坏交互编辑和产生不规范 XML 的问题，不适合整体直接提交。

要同时解决“打开像原件”和“编辑保存不破坏格式”，必须覆盖四层：

1. 旧格式导入尽量不丢信息。
2. 文件模型保留原始 OOXML、未知节点和关系。
3. 字体、表格、分节、行布局、分页遵循同一套规则。
4. 保存只改用户修改的范围，用真实 Office 基准验证结果。

**如果产品要求复杂 Word 文档也能在 Mini Office 内高保真编辑，应重新评估成熟排版与编辑内核。仅更换 DOC 转换器、继续交给当前 DOM 编辑器，不足以完成这一目标。**

## 二、提交前必须处理的缺陷

### 1. P1：内部刷新会把已有未保存编辑标为已保存

位置：`packages/document-model/src/store.ts:768`、`:785`。

`dirty = options?.dirty === true` 每次重新赋值。对已有 `dirty=true` 的文档执行默认 meta 更新，实测状态变为 `dirty=false / EDIT_READY`。
`mail-merge-controller.ts:202` 正在使用这种默认调用，实际存在触发入口。

应区分“这次操作不增加脏状态”和“清除已有脏状态”。非用户操作必须保留原来的 dirty；只有成功保存对应版本或明确丢弃修改才能清除。最好独立维护内容版本与最后保存版本，视图状态单独存放。

### 2. P1：表格适配在导入时永久改写原始列宽

位置：`packages/editor-word/src/parse.ts:1468`。

只要不是 pct 表格就调用 `fitColumnsToContent`，没有依据当前节、表格容器、单元格首选宽度和布局规则进行求解。请假单的固定布局也被直接压缩。
嵌套表格还复用页面版心，而不是父单元格的可用宽度；多节文档使用预先计算的全局宽度。

应保留 `tblGrid`、`tblW` 的类型与原始值、`tcW`、`tblLayout`、缩进和容器上下文，把求解后的显示宽度放入独立布局结果。
“表格永远不能超出版心”不足以作为全局导入规则。

### 3. P1：跨页段落的复制和裁剪破坏编辑模型与光标映射

位置：`packages/editor-word/src/WordEditor.tsx:3887`、`packages/editor-word/src/pagination.ts:243` 附近。

每页复制整段 DOM，通过负 margin 和 `overflow:hidden` 显示局部行；续页移除了 `data-paragraph-id` 并使用 `StaticParagraph`。
但外层正文是 `contentEditable=true`，StaticParagraph 没有显式阻断继承；续页可能仍被浏览器修改，却找不到段落 id 写回模型。首片 DOM 同时包含不可见的后续文字，方向键和选区也可能进入裁剪区域。

续页必须能够映射到同一个段落的正确字符范围。分页展示片段需携带模型范围，命中测试、选区、输入法、复制和输入都要使用该映射。
当前裁剪实现可以作为只读预览实验，不能直接作为编辑保真的完成态。

### 4. P1：新增 OOXML 属性没有按模式顺序输出

位置：`packages/editor-word/src/serialize.ts:161`、`:492`、`:545`。

探针实测新增属性组合输出：

- `tcPr`：`tcW → vAlign → tcMar`，应把 `tcMar` 放在 `vAlign` 前。
- `tblPr`：`tblW → tblLayout → tblCellMar → tblInd`，应把 `tblInd` 放在边框和布局属性前。
- `pPr` 中 `snapToGrid` 被放在编号/边框/底纹前，相关属性同时出现时与模式顺序不符。

现有顺序测试虽然通过，但构造样本未覆盖这些新增组合。应扩展统一的有序属性写入机制，并校验实际输出；不能用已有测试通过证明新增属性组合合法。
严格消费者可能要求修复或拒绝不符合模式的文件，本次未在 Word 中验证这些组合的实际打开结果。

### 5. P2：多行段落分页漏算段后距

位置：`packages/editor-word/src/pagination.ts:175`、`:181`。

普通多行段落和 keepLines 分支只累计 `paragraphLayout.height`，没有累计仍会由 DOM 渲染的 `spaceAfterPx`。
探针：页面正文高 100px，多行文字 80px、段后距 30px、下一段 10px，当前仍放进同一页；实际块总高为 120px。

应统一段落盒模型，明确页边界与兼容设置对段前段后距的处理；测量、分页和显示共用同一个结果。

### 6. P1：新增真实文件测试尝试写源路径，并且 CI 会静默跳过

位置：`crates/office-compat/src/lib.rs:298`；相关接口 `:75`。

测试将 `/Users/liqiang/Downloads/采购文件.doc` 当作 `name` 传入 `convert_legacy_bytes`。
Rust 的 `temp_path.join(absolute_path)` 返回绝对路径，接下来的 `fs::write` 实际尝试写源文件。当前受限权限返回 `Operation not permitted`，没有完成这次源路径写入。

测试应从仓库 fixture 只读加载、使用纯文件名转换，并验证原件哈希不变。接口也应拒绝绝对路径和含目录跳转的文件名，或始终使用自行生成的内部文件名。
此外，样本不存在时 `continue` 会让 CI 的关键真实文件测试虚假通过。

## 四、建议的根治架构

### 4.1 推荐产品路径：轻量主程序 + 可选本地兼容引擎

保留 Tauri 主界面和简单文档的自研编辑器。对 DOC 和复杂 DOCX 提供可按需安装、安装后离线工作的成熟兼容引擎。

- **查看、打印**：引擎直接读取原件，输出 PDF 或页面布局。避免先有损转 DOCX，再由当前编辑器二次排版。
- **复杂文档编辑**：接入能够承担排版、编辑和保存的成熟内核，或明确通过本机 Office 编辑；不要把“PDF 看起来正确”当作“编辑保存已经正确”。
- **简单文档编辑**：继续自研，但用明确的能力范围和语料验收；未支持对象保留并适当限制修改。
- **字体环境**：记录缺失字体和实际替代字体。安装成熟引擎不会自动补齐宋体、仿宋、方正字体，也不会自动保证与源 Word/WPS 同版。

第一阶段可用 LibreOffice Headless 验证本地转换/预览，再独立验证编辑内核方案。
Headless CLI 不等于嵌入式编辑器；LibreOfficeKit 有转换、分块渲染和编辑接口，但官方文档对相关接口有实验性/不稳定性提示，需要分别验证 macOS、Windows、输入法和打包方案。
不要在 PoC 前承诺具体下载体积、交付天数或与 Word 像素一致。

这条路线需要重新评审 ADR 0001 的运行依赖边界。现有 ADR 本身列出了“真实兼容通过率持续不足时重新评估”的条件。

### 4.2 两条编辑路线都需要的保存底座

对保留的自研编辑通道，实现原始 XML 与编辑模型的关联：

1. 保留原始 OPC 部件、命名空间、关系和未知节点。
2. 记录节点稳定标识及编辑影响范围；未编辑内容优先原样透传。
3. 只修改有把握的文本/属性范围；跨段落、编号、域、修订、批注、节属性的修改需维护关联关系。
4. 不把“复制原 ZIP，随后整篇重建 document.xml”当作无损保存。
5. 无修改保存应保持原始有效载荷；小改动另存后需回到 Word/WPS 检查新增损失。

段落级 XML 替换是过渡手段，也会丢失该段内未知对象；必须保留并合并未被编辑的子节点，或对相应段落限制编辑。

### 4.3 如果坚持完全自研

需要建设专门的 Word 布局内核：样式继承与兼容设置、字体/字形度量、逐行断行、表格约束求解、分栏/分节、浮动绕排、分页与域更新。
输出带模型字符范围的行盒/对象盒；屏幕渲染、命中测试、选区和打印读取相同结果。
这是持续的内核研发，不能用若干 CSS 规则和本次单元测试估算“已完成 F2”。

## 五、执行顺序与验收

1. **先收敛提交**：处理上述 P1，隔离生命周期、转换、排版三类改动；移出个人诊断脚本、截图和发布 ZIP，避免混在兼容性修复中提交。
2. **固定三份样本**：保留原件哈希，在原创建环境/指定版本 Word 或 WPS 中导出基准 PDF，记录字体、版本、页数。两种软件输出不同则明确目标。
3. **做引擎对照 PoC**：分别比较原件→成熟引擎页面、原件→DOCX→自研页面，区分转换损失和布局差异；只有验收通过才正式选型。
4. **做无损往返**：未编辑保存、小段文字修改保存，重新用指定 Word/WPS 打开，比较文字/表格/对象数量、页面和局部视觉差异。
5. **再扩大语料**：三份通过后增加多节、合并单元格、浮动图、页眉页脚、修订和输入法场景。指标是后续验收目标，不写成已有完成率。

三份样本的最低验收应包含：正文无丢字、表格与合并关系无新增损失、字体缺失明确可见、关键页面与分页符合指定基准、续页可正确编辑、编辑后未保存标记正确、另存后 Word/WPS 无修复提示。
